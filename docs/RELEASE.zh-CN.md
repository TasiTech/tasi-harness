# Tasi Harness 1.1.0 正式发布：本地 Hermes 桌面 AI 智能体

> 以完整 Agent 架构、浏览器操作能力和无需 embedding 的本地知识能力，推动桌面 AI 从对话工具走向执行系统

2026年4月24日，Tasi Harness 1.1.0 正式发布。**作为一款本地优先的桌面 AI Agent**，Tasi Harness 并不止于提供聊天入口，而是将会话持久化、Prompt 组装、工具调用、多轮执行、技能索引、记忆注入、任务调度与本地知识处理整合进同一套桌面运行，帮助用户在本机环境中构建更稳定、更可控、也更贴近真实业务流程的智能体工作方式。

在产品架构上，Tasi Harness 明确参考了 Hermes-Agent 风格的运行时设计思路，包括围绕任务目标组织 Prompt、驱动工具调用、根据工具结果继续迭代，并把记忆、技能和运行时上下文纳入同一条执行链路。它强调的是对这类 Agent runtime 设计方法的本地化实现，而不是直接打包原始 Python Hermes 运行时。

与传统对话式 AI 工具相比，Tasi Harness 1.1.0 **更强调“执行”而非仅仅“回答”**。产品内置完整的 Agent loop，能够围绕任务目标调用工具、读取结果、继续迭代，并在会话、技能与记忆之间形成连续上下文。这一设计使其不仅适用于即时问答，也适用于需要持续推进、反复复用和逐步沉淀流程的桌面工作场景。

**浏览器操作能力是本次版本的重要升级方向。** Tasi Harness 内置 `browser_open`、`browser_click`、`browser_type`、`browser_scroll`、`browser_wait`、`browser_extract` 等浏览器工具，可支持页面打开、元素交互、内容提取与结果回填。在实际使用中，这意味着用户可以让 Agent 不只是“理解网页”，而是真正参与网页上的信息获取与操作流程。针对不同使用习惯，Tasi Harness 同时支持应用内网页预览与外部浏览器桥接模式，为桌面级浏览器协同提供了更灵活的实现路径。

**在知识能力方面**，Tasi Harness 1.1.0 采用了一条更轻量、更贴近本地部署需求的技术路线。产品支持将 `DOCX`、`XLSX`、`PPTX`、`Markdown`、`TXT`、`JSON`、`CSV` 等文档转换为 Markdown，并在本地完成切分、索引与召回。整个个人知识库流程不依赖 embedding 管线，也不强依赖外部向量数据库，而是通过本地关键词检索结合关键词扩展机制，为对话提供相关内容支持。这种方案降低了部署复杂度与维护成本，也使知识资产能够更自然地保留在本地环境之中。

Tasi Harness 1.1.0 同样**强调工作流的可沉淀与可复用**。通过 `SKILL.md` 机制，用户可以将高频任务、稳定流程与团队经验沉淀为技能，并结合本地技能、内置技能与技能市场持续扩展能力边界。配合会话历史、持久记忆、定时任务和邮件通知，Tasi Harness 不再只是单次调用的 AI 工具，而更接近一个能够不断积累上下文、形成执行习惯并参与长期任务的桌面 Agent 基座。

**在安全与控制层面**，Tasi Harness 继续坚持保守而务实的默认策略。当前版本启用了 Electron context isolation，渲染层不直接暴露 Node.js 能力，文件工具默认受工作区限制，终端工具默认关闭，并支持按次复制工作区的沙箱执行模式。对于需要在本地环境中引入更强执行能力、同时又希望控制边界和降低风险的用户而言，这一产品设计提供了更适合长期使用的平衡方案。

**从产品定位上看**，Tasi Harness 1.1.0 面向的并不是“把聊天搬到桌面”的轻量体验，而是希望让 AI 真正进入个人工作台、团队工具链和本地业务流程的用户群体。无论是开发、运营、研究、知识整理还是需要浏览器协同与文档辅助的工作场景，Tasi Harness 都希望以参考 Hermes 运行时思路构建出的完整 Agent 架构，以及更克制的本地化设计，为桌面智能体提供一条更具可行性的落地路径。

## 关于 Tasi Harness

Tasi Harness 是一个基于 Electron、TypeScript、React 与 Vite 构建的本地优先桌面 AI Agent，支持多模型提供方接入、浏览器自动化、持久记忆、技能系统、定时任务、个人知识库与沙箱执行。产品强调本地可控、流程可复用与能力可扩展，致力于让桌面 AI 从单一对话界面演进为可持续运行的执行系统。

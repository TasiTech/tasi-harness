# 投标文件通用结构参考

本文件是 `bid-writer` 的参考模板库，不是交付物正文。使用时只抽取适合当前招标文件的结构、表格和证据槽；不得把本文件的说明、frontmatter、使用规则、示例变量或未替换占位内容写入最终标书。

## 使用边界

- 招标文件、招标公告、答疑/澄清文件给出的格式、顺序、表格、签章要求永远优先。
- 只有当招标文件没有给出完整目录或表格格式时，才用本模板补足常见标书骨架。
- 本模板适合中文招投标写作，尤其是政府采购、货物采购、系统集成、软件平台、运维服务、咨询服务等常见场景。
- 本模板不是法规模板。涉及中小企业声明、政府采购政策、资格条件、报价密封、保证金、联合体、分包等内容时，应按当前招标文件和现行有效法规重写。
- 模板变量采用 `{变量名}` 表示。生成正式文件前必须全部替换或删除。
- 证据槽采用 `{证据槽：证据类型｜来源文件｜目标章节}` 表示。正式文件中应替换为真实图片、扫描件、表格或删去，并在检查点记录处理结果。

## 模板选择

按标的类型选择主骨架。一个项目可组合多个模块，但不要强行保留不适用章节。

| 场景 | 推荐主骨架 | 常见重点 |
|---|---|---|
| 政府采购货物 | 资信商务 + 技术 + 报价 | 资格证明、产品参数、授权、报价一致性、政策功能 |
| 系统集成/平台建设 | 资信商务 + 技术方案 + 实施服务 + 报价 | 总体架构、功能响应、设备/软件配置、实施、培训、售后 |
| 软件开发/SaaS/运维服务 | 商务资格 + 服务/技术方案 + 项目管理 + 报价 | 需求理解、服务能力、人员团队、SLA、案例、交付计划 |
| 咨询/设计/评估 | 商务资格 + 服务方案 + 团队案例 + 报价 | 方法论、工作计划、人员资历、成果物、质量控制 |
| 工程/施工 | 资格商务 + 施工组织 + 安全质量 + 报价 | 施工方案、进度、人员机械、安全文明、质量保证 |

## 通用成稿结构

以下结构是兜底骨架。若招标文件给出了不同顺序，按招标文件重排。

```text
封面
目录
第一部分 资格/资信及商务文件
第二部分 技术/服务响应文件
第三部分 报价文件
招标文件要求的其他文件
```

### 封面

```text
正本 / 副本

投 标 文 件

项目名称：{项目名称}
项目编号：{项目编号}
分标/包号：{分标或包号}
投标文件名称：{资信商务/技术/报价/完整投标文件}
投标人名称：{投标人全称}
投标人地址：{注册地址或通讯地址}
日期：{提交日期}
```

### 目录

最终 Word 文件应使用真实 TOC 字段，不手工维护页码。目录层级应与正文 Heading 样式一致。

## 其他文件

仅保留招标文件明确要求或与评分相关的其他文件，例如：

- 中小企业声明、残疾人福利性单位声明、监狱企业证明等政策文件。
- 联合体协议、分包意向协议。
- 原厂授权、售后服务承诺函、制造商资格证明。
- 招标文件要求单独装袋、单独递交或电子上传的文件清单。

## 证据嵌入规则

- 每个证据图片、证书、合同、人员证明、产品彩页应进入其支持的正文小节。
- 图片页标题应使用证据主题或对应响应点，例如 `KVM 切换器产品彩页`、`软件著作权证书：广告视频发现方法及装置`。
- 不得使用 `证据图片：{文件名}`、`本页为与本节内容对应的企业资料证明图片：{路径}` 等内部提示。
- 不得创建 `附录：企业资料图片`、`附件：企业资料图片`、`剩余图片` 等兜底章节。
- 无法映射到正文的证据应写入 gap report，并在交付状态中说明 Draft/Blocked 原因。

## 不进入交付物的内容

以下内容只用于工作过程，不能写入最终投标正文：

- 本模板的 frontmatter、使用边界、模板选择说明和本节说明。
- helper script 运行记录、验证状态、工作日志、checkpoint 摘要。
- `Draft delivery` / `Blocked` 的原因说明，除非用户明确要求在单独交付说明中列出。
- 未替换的 `{变量名}`、`{证据槽：...}`、`[待补充]`、`TODO`、`TBD`。
